# 农田土壤墒情云端采集与数据分析系统

> 基于 ESP32 的低成本农田土壤墒情监测系统：四要素采集 → MQTT 上云 → 云端归档 → 网页端 / 微信小程序端实时分析与远程控制。

## 一、项目简介

传统墒情监测依赖人工采样，时效性差；商用墒情站价格高、需自建服务器与专人运维，小农户难以负担。本系统以 **ESP32** 为主控，配合电容式土壤湿度传感器、DS18B20 土温传感器与 DHT11 空气温湿度传感器，实现：

- **低成本**：核心器件成本控制在百元级，无需自建服务器；
- **零运维**：数据经巴法云 MQTT 中转，云端自动归档，两端客户端直接读取；
- **可远程运维**：阈值可在网页端/小程序端直接改，通过 MQTT 下行写入设备 NVS，断电不丢；
- **可告警**：墒情等级跃迁时经微信服务通知直达用户。

番茄仅作为案例作物，阈值参数可按作物自由调整。

## 二、系统架构

系统按 **五层** 组织，数据链路为**双向闭环**：

```
┌───────────────────────────────────────────────────────────────────┐
│  应用层        Web 网页端（纯静态）        微信小程序端              │
│                实时监测 / 历史查询 / 阈值下发 / 远程控制 / 报表导出   │
└────────┬──────────────────────────────────────────────┬───────────┘
         │ ① 实时与当天：HTTP 直连巴法云（30 s 轮询）      │ ③ 下行控制
         │ ② 历史时段：云函数 getHistory 查询归档库        │
┌────────▼──────────────────────────────────────────────▼───────────┐
│  归档层        CloudBase 云函数：每 10 min 增量同步巴法云数据        │
├───────────────────────────────────────────────────────────────────┤
│  网络层        MQTT（bemfa.com:9501，主题 Test01）· 微信服务通知     │
└────────┬──────────────────────────────────────────────▲───────────┘
         │ 上行 JSON 帧（四路读数 + 状态）                │ ④ 告警旁路
┌────────▼──────────────────────────────────────────────┴───────────┐
│  控制层        ESP32：8 点滑动均值滤波 · 5 档墒情判定 · 告警去抖      │
│                OLED 显示 · 阈值 NVS 持久化 · 灌溉继电器驱动          │
├───────────────────────────────────────────────────────────────────┤
│  感知层        HW-390 土壤湿度 · DS18B20 土温 · DHT11 空气温湿度      │
└───────────────────────────────────────────────────────────────────┘
```

四条数据链路：

| 链路 | 方向 | 说明 |
|---|---|---|
| ① 上行 | 设备 → 云端 → 客户端 | ESP32 每 30 s 采集并 MQTT 上报，客户端 HTTP 直连拉取 |
| ② 归档 | 云端内部 | 云函数增量同步至 CloudBase，供历史区间查询 |
| ③ 下行 | 客户端 → 云端 → 设备 | 客户端 postmsg 下发阈值 / 灌溉指令，ESP32 写入 NVS 并回执 |
| ④ 告警 | 设备 → 云端 → 用户 | 等级跃迁时推送微信服务通知（3 min 最小间隔去抖） |

**关键设计：客户端实时数据直连巴法云，不经云函数**；云端不可用时逐级回退（云函数 → 巴法云直连 → 浏览器本地缓存），保证可用性。

## 五、快速开始

### 5.1 固件端

1. **依赖库**（Arduino IDE → 库管理器安装）：

   | 库 | 用途 |
   |---|---|
   | `PubSubClient` | MQTT 客户端 |
   | `ArduinoJson` | JSON 帧解析与组包 |
   | `U8g2` | OLED 显示 |
   | `DHT sensor library` | DHT11 |
   | `DallasTemperature` + `OneWire` | DS18B20 |

2. **开发板**：ESP32 by Espressif（Arduino-ESP32 Core 2.x+）

3. **配置凭据**：复制 `config.example.h` 为同目录下的 `config.h`，填入自己的值：

   ```c
   #define SECRET_WIFI_SSID  "YOUR_WIFI_SSID"     // 须为 2.4 GHz 频段
   #define SECRET_WIFI_PWD   "YOUR_WIFI_PASSWORD"
   #define SECRET_BEMFA_UID  "YOUR_BEMFA_UID"     // 巴法云控制台右上角「私钥」
   ```

   > `config.h` 已被 `.gitignore` 排除，不会被提交。若不存在，固件会自动改用 `config.example.h` 的占位值（此时无法联网，仅能离线运行）。

4. **主题名**：默认为 `Test01`，如需修改，改固件 [模块 5] 的 `MQTT_TOPIC`，并同步修改网页端/小程序端配置中的 `DEFAULT_TOPIC`。

5. 编译烧录即可。上电后 OLED 显示自检信息，随后每 30 s 上报一帧。

### 5.2 网页端

**方式一：直接打开**（推荐用于本地查看）
```bash
cd web
python -m http.server 8080
# 浏览器打开 http://localhost:8080
```

**方式二：静态托管**（无需后端，可部署到任意静态托管平台：腾讯云 CloudBase、GitHub Pages、Vercel 等），把 `web/` 整个目录上传即可。

**配置 UID**：两种方式任选
- 复制 `config.js` 为 `config.local.js`，填入自己的巴法云 UID；
- 或直接在页面右上角「设置」里填写 UID，浏览器会存到 localStorage。

> ⚠️ 用 GitHub Pages 部署时 `config.local.js` 不存在，页面会提示填写 UID，属正常现象。

### 5.3 微信小程序端

1. 用**微信开发者工具**导入 `miniprogram/` 目录；
2. 在 `project.config.json` 中把 `appid` 换成自己的小程序 AppID；
3. 配置 UID：把 `config.js` 里的 `UID` 换成自己的巴法云私钥，或在「设置」页里直接填写（存本地缓存，优先级更高）；
4. 若需请求云函数，在**小程序后台 → 开发 → 开发设置 → 服务器域名**里把云函数域名加入 `request` 合法域名（只填域名，不带路径）；
5. 编译预览。

## 六、关键功能说明

### 6.1 五档墒情等级

默认阈值（可按作物调整）：`shLow = 45`、`shOpt = 65`、`shHi = 80`

| 等级 | 土壤湿度区间 | 处置 |
|---|---|---|
| 重旱 | < 30%（固定） | 告警 + 启动灌溉 |
| 轻旱 | 30% ~ shLow | 告警 + 启动灌溉 |
| 适宜 | shLow ~ shOpt | 正常 |
| 过湿 | shOpt ~ shHi | 告警 |
| 积水 | ≥ shHi | 告警 |

阈值下发时设备端会做合法性收拢（如 `shLow` 限制在 31~60、`shOpt` 须介于 `shLow+1` 与 `shHi-1` 之间），避免下发非法值导致档位消失。

### 6.2 阈值远程下发与持久化

客户端将 8 个阈值字段打包为 JSON 经 MQTT 下行 → 设备校验并写入 NVS → **立即回发一帧带阈值回执的上行数据**。客户端以设备回执为唯一真源，避免"界面显示值"与"实际生效值"不一致。断电重启后阈值不丢失。

### 6.3 告警去抖

连续多次越界才触发推送；同一状态最小推送间隔 3 min；推送失败记录时间戳后短退避重试。避免湿度在阈值附近反复横跳导致刷屏。

### 6.4 数据分析（两端一致）

- **描述统计**：均值、极值、标准差、日较差
- **相关性分析**：Pearson 相关矩阵、散点回归
- **日变化聚合**：24 小时分时均值，观察昼夜节律
- **趋势预测**：ARIMA(0,1,1) 单步滚动预测，θ 在 60 点滑动窗口内最小二乘估计，附 95% 不确定度带（±1.96 × 残差标准差）
- **报表导出**：原始数据与分析结果导出为 Excel

> 预测模型为透明可解释的轻量时序模型，端侧纯 JS 实现，不依赖服务端。实测中一步预测精度与 Naive 持久性基准基本持平——原因是土壤湿度序列变化极平缓，故本系统定位为**趋势监测与阈值告警**，而非高精度数值预测。

## 八、常见问题

**Q：网页端打开只显示"请填写 UID"？**
A：`config.local.js` 未创建。复制 `config.js` 为 `config.local.js` 并填入 UID，或在页面设置里填写。

**Q：小程序连不上数据？**
A：检查三点——UID 是否正确、主题名是否与固件 `MQTT_TOPIC` 一致、开发者工具是否勾选"不校验合法域名"（或已在小程序后台配置 request 合法域名）。

**Q：历史数据查不到？**
A：历史区间依赖云端归档，若归档服务不可用，客户端会自动回退到巴法云直连（最近约 5000 条 ≈ 41 h）或浏览器本地缓存。当天实时数据始终走直连，不受归档影响。

**Q：数据刷新比设定的间隔慢？**
A：页面刷新的是"拉取频率"，实际上报频率由设备端 `REPORT_INTERVAL` 决定。若长期无新数据，检查设备是否离线或上报失败。
